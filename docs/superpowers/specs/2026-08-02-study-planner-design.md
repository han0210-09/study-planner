# 스터디 플래너 설계 문서

작성일: 2026-08-02

## 1. 개요

종이 스터디 플래너(참고 사진)를 모바일 웹앱으로 옮긴다. 앱을 켜면 월간 달력이 뜨고, 날짜를 누르면 그날의 하루 플래너(To-Do + 05:00~익일 02:00 타임테이블)가 열린다.

**목표**

- 폰 브라우저에서 종이 플래너와 같은 감각으로 하루 계획을 세우고 체크한다.
- 5분 단위로 시간 블록을 지정한다.
- 반복되는 계획을 하루/주 단위로 복사해 기간을 지정해 붙여넣는다.
- 수행평가·시험 같은 일정을 달력에 표시하고 D-day로 카운트한다.

**비목표 (v1에서 제외)**

- 계정 로그인, 클라우드 동기화 (데이터 모델에 확장 지점만 남긴다)
- 알림/푸시, 통계 대시보드, 공휴일 자동 표시, 다중 사용자

## 2. 확정된 결정사항

| 항목 | 결정 |
|---|---|
| 저장 | 오프라인 우선. `localStorage` 단일 키. 동기화는 후속 작업 |
| 배포 | `src/`를 모듈로 개발 → `build.js`가 `dist/planner.html` 한 장으로 인라인 → Artifact로 퍼블리시 |
| 타임테이블 입력 | 길게 눌러 드래그로 블록 생성(5분 스냅) + 탭하여 5분 단위 정밀 보정 |
| 계획 vs 실제 | 블록마다 완료 체크. 목표시간 = 전체 블록 합, 실제시간 = 완료 블록 합 |
| 복사/붙여넣기 | 하루 또는 일주일을 복사 → 범위(주/월/년/직접) + 요일 필터로 붙여넣기 |
| 일정 | 날짜에 일정 등록(제목·유형·색·기간) + 가장 가까운 일정까지 D-day 자동 계산 |

## 3. 핵심 개념

### 3.1 플래너 날짜와 하루 경계

계획 범위가 새벽 2시까지 이어지므로 **하루의 경계를 오전 4시**로 둔다.

- 실제 시각이 `00:00~03:59`이면 플래너 날짜는 **전날**이다.
- 새벽 1시에 앱을 켜면 지금 하고 있는 공부에 바로 체크할 수 있다.
- `02:00~05:00` 사이는 계획 대상이 아니므로 경계를 4시로 잡아도 블록이 잘리지 않는다.

`SP.datetime.plannerDate(now)` 가 이 규칙을 담당하며, 앱 전체는 이 함수가 돌려준 날짜만 "오늘"로 취급한다.

### 3.2 시간 표현

타임테이블의 시각은 **그날 자정으로부터의 분(minute)** 정수로 저장한다.

- 범위: `300`(05:00) ~ `1560`(익일 02:00). 총 1260분 = 21시간 = 5분 슬롯 252칸.
- `start`, `end`는 항상 5의 배수. 최소 블록 길이 5분(`end - start >= 5`). 5분보다 짧게 드래그하면 5분으로 만든다.
- 12:00 이후는 그대로 이어지고, 24:00 이후는 `1440` 이상으로 표현한다(예: 01:30 = `1530`).

정수 연산만으로 스냅·겹침 검사·시간 합계가 처리되므로 시간대나 서머타임 문제가 발생하지 않는다.

### 3.3 블록 겹침 금지

종이 플래너와 같이 타임테이블은 단일 트랙이다. 블록끼리 겹칠 수 없다.

- 드래그로 생성할 때 기존 블록에 닿으면 그 지점에서 멈춘다.
- 편집으로 겹치게 만들려 하면 저장을 거부하고 안내 문구를 띄운다.

## 4. 데이터 모델

`localStorage` 키 `studyPlanner.v1` 에 아래 객체를 JSON으로 저장한다.

```js
{
  version: 1,

  settings: {
    subjects: [ { id: "s1", name: "국어", color: "#ffe066" } ],
    dayBoundaryHour: 4
  },

  days: {
    "2026-08-02": {
      achievement: 70,            // 학습 성취도 0~100
      memo: "...",
      todos: [
        { id: "t1", subjectId: "s1", text: "문학 문제집 20p", done: true }
      ],
      blocks: [
        { id: "b1", subjectId: "s3", text: "미적분", start: 540, end: 660, done: false }
      ],
      updatedAt: 1785000000000
    }
  },

  events: [
    { id: "e1", title: "국어 수행평가", type: "assessment",
      color: "#ff8787", startDate: "2026-08-14", endDate: "2026-08-14", memo: "" }
  ],

  clipboard: { kind: "day", copiedAt: 1785000000000, payload: { /* 아래 6.1 참고 */ } }
}
```

**규칙**

- 날짜 키는 로컬 기준 `YYYY-MM-DD` 문자열. UTC 변환을 거치지 않는다.
- 계획이 없는 날은 `days`에 키 자체가 없다. 빈 날을 저장하지 않는다.
- `updatedAt`은 날짜별 최종 수정 시각. 후속 클라우드 동기화에서 최신 판정에 쓰기 위한 자리다.
- 일정 유형(`type`)은 `assessment`(수행평가) / `exam`(시험) / `homework`(과제) / `etc`(기타).
- 하루짜리 일정은 `startDate === endDate`.

**저장 정책**

- 변경 발생 후 300ms 디바운스하여 한 번에 직렬화·저장한다.
- 저장 직전 스키마 검증을 통과한 데이터만 쓴다.

## 5. 화면

### 5.1 월간 달력 (첫 화면)

- 앱 시작 시 `plannerDate(new Date())` 기준 이번 달을 렌더하고 오늘 칸에 강조 링을 그린다.
- 헤더: `‹ 2026년 8월 ›`, "오늘" 버튼.
- 요일 헤더는 일요일 시작. 일요일 빨강, 토요일 파랑.
- 각 날짜 칸:
  - 날짜 숫자
  - **일정 배지** — 유형 색 점 + 짧은 제목, 최대 2개. 초과분은 `+N`
  - **공부량 막대** — 그날 실제시간(완료 블록 합)을 그 달 최대값 대비 비율로 그린 가로 바. 그 달 최대값이 0이면 막대를 그리지 않는다
  - **성취도** — 기록된 경우 작게 `70%`
- 하단 요약: 이번 달 총 공부시간, 평균 달성률.
- 날짜 **탭** → 하루 화면. 날짜 **길게 누르기** → 빠른 메뉴(복사 / 붙여넣기 / 일정 추가).
- 앱을 켜둔 채 날짜가 바뀌면 자동 갱신한다(`visibilitychange` + 60초 타이머로 `plannerDate` 변화 감지).

### 5.2 하루 플래너

세로 스크롤. 위에서부터:

1. **헤더** — `D-12`(가장 가까운 일정까지) · `2026. 8. 2. (일)` · `‹ ›` 전날/다음날 · `⋯` 메뉴(이 날 복사 / 붙여넣기 / 일정 추가 / 하루 초기화) · `←` 달력으로
   - "하루 초기화"는 그날의 `todos`, `blocks`, `achievement`, `memo`를 모두 지운다. 확인 대화상자를 거친다. 일정은 지우지 않는다
2. **학습 성취도** — 0~100% 슬라이더
3. **오늘의 일정** — 해당 날짜에 걸친 일정이 있으면 카드로 표시
4. **To-Do List** — 항목마다 `[과목 태그] [할 일] [체크박스]`. 추가·수정·삭제·순서변경(위/아래 버튼). 체크 시 취소선
5. **타임테이블** — 아래 5.3
6. **목표시간 / 실제시간** — `목표 8시간 20분 / 실제 6시간 45분` + 달성률 바. 자동 계산이며 수동 입력 불가
7. **메모** — 자유 텍스트

### 5.3 타임테이블 상호작용

- 왼쪽에 시간 눈금(1시간 단위 라벨, 5분 눈금선), 오른쪽에 블록 트랙.
- **길게 눌러 드래그(300ms)** → 블록 생성. 이동 중 5분 단위로 스냅되며 시작~종료 시각이 실시간 표시된다. 기존 블록에 닿으면 그 지점에서 멈춘다.
- 생성 직후 편집 시트가 열려 과목·내용을 입력한다. 시트를 취소하면 블록을 만들지 않는다.
- **블록 탭** → 편집 시트: 과목 선택(색 자동), 내용, 시작/종료 `−`/`+` 5분 버튼, 삭제.
- **블록 위·아래 끝 드래그** → 길이 조절(5분 스냅, 겹침 지점에서 멈춤).
- **블록의 체크 아이콘 탭** → 완료 토글. 완료 시 채도가 진해지고 ✓ 표시. 이 값이 실제시간에 합산된다.
- 표시 중인 날짜가 플래너 기준 오늘이면 **현재 시각선**(빨간 가로선)을 그린다.

### 5.4 과목 관리

- 기본 과목: 국어, 영어, 수학, 사회, 과학, 한국사, 기타. 형광펜 톤 파스텔 색상.
- 설정 화면에서 추가·이름변경·색변경·삭제.
- 삭제 시 그 과목을 참조하던 블록/투두는 `subjectId: null`이 되어 회색 기본색으로 렌더된다. 삭제 확인 대화상자에 영향받는 항목 수를 표시한다.

## 6. 복사 / 붙여넣기

### 6.1 복사

클립보드 슬롯은 하나이며, 마지막 복사가 이전 것을 대체한다.

- **하루 복사** — `{ kind: "day", payload: { todos, blocks } }`
- **주 복사** — `{ kind: "week", payload: { byWeekday: { 0: {todos, blocks}, ..., 6: {...} } } }` (0 = 일요일)

복사 대상은 **계획만**이다.

- `done`은 전부 `false`로 초기화한다.
- `achievement`, `memo`, 일정은 복사하지 않는다.
- 항목 id는 붙여넣을 때 새로 발급한다.

### 6.2 붙여넣기

시트에서 세 가지를 지정한다.

| 옵션 | 값 |
|---|---|
| 범위 | 이 날 / 이번 주 / 이번 달 / 올해 / 직접 기간 선택 |
| 요일 필터 | 전체 / 평일만 / 주말만 / 요일 개별 선택 |
| 기존 계획 처리 | 덮어쓰기 / 겹치지 않는 것만 추가 / 계획 있는 날 건너뛰기 |

**범위 해석 규칙**

- 기준일은 **붙여넣기를 실행한 화면의 날짜**다(하루 화면이면 그 날, 달력 빠른 메뉴면 길게 누른 날).
- "이번 주"는 기준일이 속한 주이며 **일요일 시작 ~ 토요일 끝**이다. 달력 표시와 같다.
- "이번 달"은 기준일이 속한 달의 1일~말일, "올해"는 기준일이 속한 해의 1/1~12/31이다.
- 범위 안의 **과거 날짜도 포함**한다. 미래만 원하면 "직접 기간 선택"을 쓴다.
- 요일 필터의 "평일"은 월~금, "주말"은 토·일이다.

- 적용 전 `"총 22일에 적용됩니다"` 미리보기를 표시한다.
- **덮어쓰기** — 대상 날의 `todos`, `blocks`를 완전히 교체한다.
- **추가** — 시간이 겹치지 않는 블록만 넣고, 겹치는 블록은 건너뛴다. 투두는 전부 추가한다. 건너뛴 개수를 결과로 알린다.
- **건너뛰기** — 대상 날에 `todos` 또는 `blocks`가 하나라도 있으면 그 날을 건드리지 않는다.
- `kind: "week"`이면 대상 날짜의 요일에 해당하는 소스 요일 계획을 적용한다. 해당 요일에 소스가 없으면 그 날은 건너뛴다.
- `achievement`, `memo`는 어느 모드에서도 유지된다.

대상 날짜 계산은 `SP.clipboard.resolveTargetDates(range, weekdayFilter, baseDate)` 순수 함수가 담당하며 테스트로 고정한다.

## 7. 일정과 D-day

- 등록: 달력에서 날짜 길게 누르기 → "일정 추가", 또는 하루 화면 `⋯` 메뉴.
- 필드: 제목, 유형(수행평가/시험/과제/기타), 색, 시작일, 종료일, 메모.
- 여러 날에 걸친 일정(시험기간)은 그 범위의 모든 날짜 칸에 배지로 표시된다.
- 지난 일정은 회색 처리한다.
- **D-day** — 기준 날짜(플래너 날짜) **당일을 포함한 이후**에서 `startDate`가 가장 가까운 일정까지의 일수.
  - 당일이면 `D-DAY`, 미래면 `D-12`, 예정 일정이 없으면 헤더에 `일정 없음`.
  - 기간형 일정은 `startDate` 기준으로 계산한다.

**모듈 규약**

각 파일은 아래 UMD-lite 껍데기를 쓴다. 브라우저에서는 `<script>` 태그로 그냥 로드되고, Node 테스트에서는 `require`로 불러온다. 번들러나 npm 의존성이 필요 없다.

```js
(function (root) {
  const datetime = { /* ... */ };
  root.SP = root.SP || {};
  root.SP.datetime = datetime;
  if (typeof module !== "undefined") module.exports = datetime;
})(typeof globalThis !== "undefined" ? globalThis : window);
```

**의존 방향**

```
datetime  ←  store  ←  subjects / events / clipboard  ←  todos / timetable  ←  day / calendar  ←  app
```

- 뷰 모듈은 반드시 `store`를 통해서만 데이터를 읽고 쓴다. 뷰끼리 직접 호출하지 않는다.
- 화면 전환은 `app.js`가 독점한다. `SP.app.showCalendar(year, month)` / `SP.app.showDay(dateKey)` 두 함수만 화면을 바꾼다. `calendar.js`는 날짜가 눌렸다는 사실만 콜백으로 올려보내고, 자기가 직접 하루 화면을 띄우지 않는다.
- `app.js`는 부팅 시 `store`를 로드하고, 플래너 날짜 변화 감시(`visibilitychange` + 60초 타이머)도 담당한다.

**빌드**

`build.js`는 `src/index.html`을 읽어 `<link rel="stylesheet">`와 `<script src>`를 각각 파일 내용으로 치환한 `dist/planner.html`을 만든다. 의존 순서는 `index.html`의 스크립트 태그 순서를 그대로 따른다. 외부 리소스(폰트·CDN)는 사용하지 않으므로 결과물은 완전히 자립적이다.

## 9. 오류 처리

| 상황 | 처리 |
|---|---|
| 저장 실패 (용량 초과, 프라이빗 모드) | 상단에 지속되는 경고 배너 표시. 조용히 무시하지 않는다 |
| 손상된 저장 데이터 | 읽기 시 스키마 검증. 실패하면 `studyPlanner.v1.corrupt.<timestamp>` 키로 원본을 보존하고 초기 상태로 시작. 사용자에게 알린다 |
| 잘못된 블록 (`end <= start`, 범위 밖, 5의 배수 아님, 겹침) | 저장 단계에서 거부하고 편집 시트에 사유를 표시 |
| 존재하지 않는 `subjectId` 참조 | `null`로 취급해 회색 렌더. 오류로 처리하지 않는다 |
| 알 수 없는 `version` | 상위 버전이면 읽기 전용 안내 후 중단. 데이터를 덮어쓰지 않는다 |

**백업** — 설정 화면에 JSON 내보내기 / 불러오기를 둔다. 기기 이전과 사고 복구 수단이며, 클라우드 동기화 전까지의 안전장치다.

## 10. 테스트

`node --test test/` (Node 18+, 현재 환경 v24.18.0). 외부 의존성 없음.

UI 드래그와 렌더링은 자동 테스트 비용이 높아 브라우저에서 수동 확인한다. 대신 **틀렸을 때 조용히 데이터가 망가지는 순수 로직**을 전부 테스트한다.

- **datetime** — 분↔시각 문자열 변환, 5분 스냅(내림/올림/경계), `plannerDate` 하루 경계 4시 처리(23:59 / 00:00 / 03:59 / 04:00), 범위 클램프
- **clipboard** — `resolveTargetDates`의 범위별 결과(주/월/년/직접), 요일 필터 조합, 월말·윤년 경계, 충돌 정책 3종의 결과 상태
- **events** — D-day 계산(당일·미래·과거·일정 없음), 기간형 일정의 날짜별 포함 판정, 가장 가까운 일정 선택
- **store** — 블록 겹침 검증, 유효하지 않은 블록 거부, 손상 데이터 복구 경로, 빈 날 정리, 마이그레이션 가드

## 11. 모바일 대응

- `viewport` 메타에 `viewport-fit=cover`, 안전영역(`env(safe-area-inset-*)`) 패딩 적용.
- 최소 터치 타겟 44px.
- 타임테이블 트랙에 `touch-action: none`을 걸어 드래그 중 스크롤이 개입하지 않게 한다.
- iOS 홈 화면 추가를 위한 `apple-mobile-web-app-capable`, `apple-mobile-web-app-status-bar-style`, `theme-color` 메타 태그.
- 웹 앱 매니페스트는 단일 HTML 제약상 `data:` URI로 시도하되 필수 요건은 아니다. 매니페스트 없이도 홈 화면 바로가기로 정상 동작한다.
