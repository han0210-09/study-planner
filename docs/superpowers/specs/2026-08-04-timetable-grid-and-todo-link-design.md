# 격자 타임테이블 + To-Do 연동 설계

날짜: 2026-08-04
상태: 승인됨
선행 스펙: `2026-08-02-study-planner-design.md`

## 배경

현재 타임테이블은 `.tt-track` 하나에 블록을 절대 위치로 얹은 세로 막대다. 시간을
지정하려면 세로로만 끌 수 있는데, 세로 드래그는 페이지 스크롤과 겹치므로 300ms
길게 누르기로 구분하고 있다.

사용자 요구:

1. 한 줄을 한 시간으로 보는 격자로 바꾸고, 한글에서 글자를 끌듯 가로로 끌다가
   아래로 내리면 그것까지 이어서 선택되게 한다.
2. 블록 끝에 틈이 있으면 그 자리에 ⊕ 를 띄워 탭 한 번으로 이어서 블록을 만든다.
3. 타임테이블 블록과 To-Do 항목을 연동한다.

## 목표

- 격자 위에서 흐름 선택(reading-order selection)으로 시간을 지정한다.
- 블록 뒤 빈 자리에서 탭 한 번으로 다음 블록을 만든다.
- 블록과 할 일이 한 쌍으로 움직인다. 완료 체크는 어느 쪽에서 하든 반대쪽에 반영된다.

## 비목표

- **가장자리 자동 스크롤.** 화면 밖까지 끌 때 자동 스크롤하는 기능은 넣지 않는다.
  현실적인 블록(30분~3시간 = 1~3행)은 한 화면에 들어오고, 21시간짜리 블록을 한 번에
  만들 일은 없다. 지금도 없는 기능이므로 이번 변경이 만드는 문제도 아니다.
- **동기화 계층.** 여전히 오프라인 전용이다.
- **기존 데이터 마이그레이션.** 이미 저장된 블록은 `todoId` 없이 그대로 동작한다.
  과거 날짜의 할 일 목록을 소급해서 다시 쓰지 않는다.

## 진행 단계

두 단계로 나눠 구현한다. 1단계를 배포해 실제 폰에서 확인한 뒤 2단계로 넘어간다.
격자를 만지는 도중에 연동 때문에 데이터 구조를 두 번 갈아엎지 않기 위해서다.

- **1단계**: 격자 + 흐름 드래그 + ⊕
- **2단계**: To-Do 연동

스키마 변경(`block.todoId`)은 2단계에 속하지만, 1단계에서 블록을 다루는 코드가
`todoId`를 지우지 않도록 처음부터 보존한다.

# 1단계 · 격자 타임테이블

## 기하

- `DAY_START = 300`(05:00), `DAY_END = 1560`(익일 02:00), `SPAN = 1260분 = 21시간`
- **21행 × 12칸.** 한 행 = 1시간, 한 칸 = 5분. 전체 252칸.
- 행 높이 **44px** → 격자 높이 924px. 현재 세로 막대(1176px)보다 짧아진다.
- 왼쪽 시각 라벨 거터 **34px**.
- 390px 폭 기준 칸 너비 ≈ 25px. 탭이 아니라 드래그의 단위이므로 44px 탭 타깃
  규칙의 대상이 아니다. 정밀 보정은 기존 ±5분 스테퍼가 맡는다.

## DOM 구조

CSS Grid 하나에 전부 얹는다. `grid-template-columns: 34px repeat(12, 1fr)`,
`grid-auto-rows: 44px`.

| 요소 | 배치 |
|---|---|
| 시각 라벨 | `grid-column: 1; grid-row: r+1` |
| 행 배경 (5분 눈금) | `grid-column: 2 / -1; grid-row: r+1`, `repeating-linear-gradient` |
| 블록 조각 | `grid-column: c+2 / span n; grid-row: r+1` |
| 고스트 조각 | 블록 조각과 동일 |
| ⊕ | 틈 첫 칸의 `grid-column / grid-row` |
| 현재 시각선 | 해당 행 안에 `position: absolute`, `left: 분/60*100%` |

퍼센트로 top/height를 계산해 절대 배치하지 않는다. 정렬은 브라우저가 책임진다.
소스 순서로 겹침이 결정되므로 **행 배경 → 블록 → ⊕ → 고스트 → 현재 시각선** 순으로
넣는다.

## 블록 조각 분할

블록 1개 = DOM 1개였던 것이 블록 1개 = 조각 1~21개가 된다. 05:50~06:20 블록은:

```
조각1: row 0, col 10, span 2   (05:50~06:00)
조각2: row 1, col  0, span 4   (06:00~06:20)
```

조각 역할:

| 조각 | 역할 |
|---|---|
| **가장 넓은 조각** | ✓ 버튼, 과목·내용 라벨, 시각 표시 |
| **첫 조각** | 왼쪽 모서리 둥글게, 시작 리사이즈 손잡이 |
| **마지막 조각** | 오른쪽 모서리 둥글게, 종료 리사이즈 손잡이 |

라벨을 첫 조각에 넣으면 안 된다. 05:55~08:00 같은 블록은 첫 조각이 25px 한 칸이라
글자가 통째로 잘린다. 조각이 하나뿐이면 세 역할을 그 조각이 모두 맡는다.
넓이가 같은 조각이 여럿이면 **앞선 조각**이 라벨을 맡는다.

**정확히 시각에 끝나는 블록에 빈 조각을 만들면 안 된다.** 06:00~07:00은 조각이
1개다(row 1, col 0, span 12). 07시 행에 span 0짜리 조각이 붙으면 안 된다.

## 드래그

### 진입 조건 두 가지

```
pointerdown ─┬─ |dx| > 8 이고 |dx| > |dy|  ──┐
             └─ 300ms 그대로 유지          ──┴─→ 선택 시작
                                               (touch-action: none, setPointerCapture)
                                               이후 방향 무관
|dy| > 8 이고 |dy| >= |dx| → 타이머 취소, 페이지 스크롤에 넘김
```

대각선으로 끌 때 어느 쪽이 이기는지 정해둬야 한다. **더 많이 움직인 축이 이긴다.**
가로가 더 크면 선택, 세로가 크거나 같으면 스크롤이다. 8px를 넘긴 첫 `pointermove`
에서 한 번 판정하고 번복하지 않는다.

격자는 평소 `touch-action: pan-y`다. 세로 스와이프는 브라우저가 가져가고 가로
스와이프만 앱에 온다. 선택이 시작된 뒤에만 `none`으로 바꿔 아래로 내려도 스크롤
대신 선택이 이어지게 한다. 진입 조건만 둘이고 그 뒤 상태 기계는 하나다.

기존 `MOVE_TOLERANCE = 8`, `LONG_PRESS_MS = 300`을 그대로 쓴다.

### 좌표 → 분

```
칸 너비 = 격자 데이터 영역 너비 / 12
행 높이 = 격자 데이터 영역 높이 / 21
col = clamp(floor((x - left) / 칸 너비), 0, 11)
row = clamp(floor((y - top)  / 행 높이), 0, 20)
분   = DAY_START + row*60 + col*5
```

라벨 거터(34px)는 데이터 영역에서 제외한다.

### 셀 포함 선택

지금은 경계에서 경계까지 잡히지만, 격자에서는 **손가락이 얹힌 칸이 포함**되어야
한다(한글에서 글자를 끌 때처럼). 05:20 칸에서 06:00 칸까지 끌면 지금은 40분,
바뀐 뒤에는 45분이다.

`store.limitRange()`는 **건드리지 않는다.** 이 함수는 분 단위 정수로만 판단하고
79개 테스트로 계약이 고정돼 있다. 대신 넘기는 인자를 바깥에서 보정한다:

```
cursor >= anchor  →  limitRange(blocks, anchor,        cursor + 5)
cursor <  anchor  →  limitRange(blocks, anchor + 5,    cursor)
```

뒤로 끌 때 anchor에 +5를 주는 이유: `limitRange`는 `a`(anchor)를 기준으로 블록이
위쪽인지 아래쪽인지 판정한다. anchor 칸 자체를 결과에 포함시키려면 anchor 칸의
**끝**을 넘겨야 한다. pointerdown이 블록 위에서 시작하면 무시되므로(`closest(".tt-block")`)
anchor 칸은 항상 비어 있고, 따라서 `b.end <= a`로 잘못 잡히는 블록은 없다.

## ⊕ 이어서 만들기

### 위치

블록이 끝나는 지점이 곧 틈의 첫 칸이다. **⊕ 는 블록 위가 아니라 틈의 첫 칸**에
놓는다. 07:00에 끝나는 블록이면 06시 행 오른쪽 끝이 아니라 07시 행 첫 칸에 뜬다.
읽는 순서대로 "여기부터 이어서"가 된다.

```
       :00  :10  :20  :30  :40  :50
  06 │ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓│  수학
  07 │ ⊕ ░░░░░░░░░░░░░░░░░░░░░░░│  ← 여기
  08 │ ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░│  영어
```

띄우지 않는 경우:

- 틈이 5분 미만 (블록이 못 들어감)
- 다음 블록이 바로 붙어 있음 (틈 없음)
- 블록이 `DAY_END`에서 끝남

### 길이

**직전 블록과 같은 길이.** 50분씩 연달아 공부하는 식이 가장 흔하고 예측이 된다.
틈이 그보다 좁으면 틈 전체를 쓴다.

```
틈의 끝 = 시작 시각이 block.end 이상인 블록 중 가장 이른 것의 start
          (그런 블록이 없으면 DAY_END)
start   = block.end
end     = min(block.end + (block.end - block.start), 틈의 끝)
```

### 탭과 드래그가 안 싸우게

⊕ 가 놓인 칸에서 **드래그도 시작할 수 있어야 한다.** 안 그러면 그 칸만 드래그
사각지대가 된다.

⊕ 버튼은 `pointerdown`을 가로채지 않고 **`click`만** 받는다.

- 툭 누르면 → ⊕ 동작 (직전 길이만큼 블록 생성)
- 끌면 → 평소대로 드래그 선택

**드래그가 시작됐다면 뒤따라오는 `click`은 무시해야 한다.** 안 그러면 그 칸에서
길게 눌러 드래그해놓고 손을 뗀 순간 ⊕ 가 블록을 하나 더 만든다. 실제로 밟게 될
함정이므로 테스트로 고정한다.

생성 후에는 드래그로 만들 때와 똑같이 `openBlockEditorOrRollback`으로 편집 시트가
열린다.

## 리사이즈

손잡이가 가로 띠에서 **세로 띠**로 바뀐다. 첫 조각의 왼쪽 모서리가 시작,
마지막 조각의 오른쪽 모서리가 종료다.

끄는 동안에는 **고스트를 그리고 블록은 흐리게(opacity .3)** 한다. 지금처럼
`style.top/height`를 직접 만지지 않는다. 조각이 여러 개면 직접 재배치하는 것보다
고스트 한 벌을 다시 그리는 쪽이 단순하고, 생성 드래그와 미리보기 경로가 하나로
합쳐진다.

## 현재 시각선

현재 시각이 속한 행 안에 세로선으로 그린다. 오늘 날짜이고 05:00~02:00 범위일
때만 나온다. 기존 판정 로직(`DAY_BOUNDARY_HOUR` 보정 포함)을 그대로 쓴다.

## 모듈

새 모듈 `src/grid.js` — 순수 함수만, DOM 없음, Node에서 테스트 가능.
`store.js`가 `limitRange`를 갖고 있는 것과 같은 구조다.

```
COLS = 12, ROWS = 21
rowColOf(minutes)                   → { row, col }
segmentsOf(start, end)              → [{ row, col, span, start, end }]
selectionArgs(anchorMin, cursorMin) → { anchor, cursor }   // limitRange에 넘길 값
plusSlotFor(blocks, block)          → { start, end } | null // ⊕ 가 만들 블록
```

`src/timetable.js`는 렌더와 드래그를 다시 쓴다. `openBlockEditor`,
`openBlockEditorOrRollback`, `saveBlocks`, `blocksOf`는 그대로 둔다.

`src/styles.css`에서 `.tt-track/.tt-hour/.tt-tick/.tt-block/.tt-handle` 계열을
격자용으로 교체한다. **같은 특이도의 규칙을 뒤에 덧붙여 앞의 값을 덮지 않도록**
기존 규칙을 남겨두지 말고 지운다.

`src/index.html`에 `grid.js`를 `store.js` 뒤, `timetable.js` 앞에 넣는다.

# 2단계 · To-Do 연동

## 규칙

1. **블록을 만들면 할 일이 생긴다.** 새 블록의 편집 시트를 저장하면 같은 과목·내용의
   할 일이 To-Do List에 추가되고 `todoId`로 연결된다.
2. **할 일 시트는 배정된 시간을 목록으로 다룬다.** 0개·1개·여러 개가 같은 모양이다.
   - `+ 시간 추가` → **첫 번째 빈 구간의 시작부터 1시간**(1시간이 안 들어가면 가장 넓은
     빈 구간 전체)을 한 줄 더한다. 5분도 안 남으면 "빈 시간이 없습니다"를 띄우고
     아무것도 더하지 않는다.
   - 줄을 누르면 펼쳐져 ±5분 스테퍼가 나온다. 한 번에 한 줄만 펼친다.
   - `✕` 로 그 줄만 뺀다. 저장할 때 목록에서 빠진 블록은 사라진다.
   - 겹침은 다른 할 일의 블록뿐 아니라 **아직 저장 안 된 이 목록의 다른 줄**과도 본다.
     안 그러면 한 할 일 안에서 시간이 겹친 채 저장된다.
   - 범위 하나만 받는 설계로는 "한 할 일에 여러 시간"을 표현할 수 없어 막다른 길이
     생긴다. `commitTodo` 는 범위 **목록**을 받는다.
3. **완료는 양방향이다.**
   - 블록 ✓ → 그 할 일에 연결된 블록이 **전부** ✓ 일 때 할 일 ☑
   - 블록 ✓ 해제 → 할 일 ☐
   - 할 일 ☑ → 연결된 블록 전부 ✓
   - 할 일 ☐ → 연결된 블록 전부 ✓ 해제
4. **과목·내용은 항상 같다.** 어느 쪽에서 고쳐도 반대쪽이 따라간다.
5. **삭제는 양쪽 대칭이다.**
   - 할 일 삭제 → 연결된 블록도 함께 삭제된다. 확인 문구에 몇 개인지 명시한다.
   - 블록 삭제 → 연결된 할 일도 함께 삭제된다. **단 그 할 일의 마지막 블록일 때만이다.**
     아침·저녁으로 나눠 잡아둔 할 일에서 하나만 지웠는데 할 일까지 지우면, 손대지도
     않은 나머지 블록이 딸려 사라진다.
   - 연결을 바꾸는 것(다른 할 일 선택, "연결 안 함")은 삭제가 아니다. 블록을 잃은
     옛 할 일은 "미배정"으로 남는다.
6. **표시.** 할 일 행에 배정 시각(`06:00~07:30`) 또는 `미배정` 칩을 붙인다. 블록
   쪽 표시는 바뀌지 않는다.

## 스키마

`block.todoId: string | null` 하나만 추가한다. 할 일에는 `blockId`를 두지 않고
`blocks.filter(b => b.todoId === todo.id)`로 역참조한다. 한쪽에만 링크를 두면
어긋난 쌍이 생길 수 없고, 할 일 하나에 블록 여러 개인 경우도 그대로 처리된다.

블록 편집 시트의 "할 일" 칸에서 고를 수 있는 값:

- `[새 할 일로 추가]` (새 블록 기본값)
- 그 날의 기존 할 일
- `[연결 안 함]` (식사·이동처럼 할 일이 아닌 블록, 그리고 기존 데이터의 상태)

빈 내용으로 저장된 블록의 할 일 텍스트는 `block.text || 과목명 || "이름 없음"`으로
정한다. 빈 할 일이 생기지 않게 하되 새 검증 규칙을 만들지 않는다.

## 복사·붙여넣기 재매핑

`materialize()`는 붙여넣을 때 todos와 blocks의 id를 전부 새로 발급한다. `todoId`를
그대로 두면 붙여넣은 블록이 **원본 날짜의 할 일**을 가리켜 연동이 엉뚱하게 동작한다.

페이로드에는 id를 담지 않는 기존 설계를 유지하고 **위치 색인**을 담는다:

- `cloneBlocks(blocks, todos)` → `todoIndex: todos.findIndex(t => t.id === b.todoId)` (없으면 -1)
- `materialize(payload)` → `todoId = todoIndex >= 0 ? fresh.todos[todoIndex].id : null`

`merge` 모드에서 블록이 겹쳐 버려지면 그 할 일은 남아 미배정이 된다. 계획 항목은
살아 있고 시각만 없는 상태이므로 의도한 결과다.

## sanitizeState

`todoId`를 읽어들이되, 그 날의 todos에 없는 값이면 `null`로 떨어뜨리고 블록은
살린다. JSON 가져오기로 깨진 링크가 들어올 수 있다. 이때 `mark()`를 호출해
복구 배너를 띄운다.

## 모듈

새 모듈 `src/link.js` — 하루치 `{ todos, blocks }`를 받아 정합성을 맞춘 새
`{ todos, blocks }`를 돌려주는 순수 함수만 둔다. DOM도 store도 모른다.

```
setBlockDone(day, blockId, done)          → { todos, blocks }
setTodoDone(day, todoId, done)            → { todos, blocks }
syncPair(day, todoId, { subjectId, text })→ { todos, blocks }
removeBlock(day, blockId)                 → { todos, blocks }   // 할 일은 남김
removeTodo(day, todoId)                   → { todos, blocks }   // 블록도 지움
firstFreeSlot(blocks, duration)           → { start, end } | null
blocksOfTodo(day, todoId)                 → Block[]
```

`todos.js`와 `timetable.js`는 이 함수들을 호출해 결과를 `setDay`에 넘긴다.

## 순수 로직 (`node --test`, 인자 없음)

**grid.js**

- `segmentsOf(360, 420)` (06:00~07:00) → 조각 1개, `{row:1, col:0, span:12}`.
  07시 행에 span 0 조각이 생기면 안 된다.
- `segmentsOf(350, 380)` (05:50~06:20) → 조각 2개
- `segmentsOf(300, 1560)` (전체) → 조각 21개
- `segmentsOf(300, 305)` → 조각 1개, span 1
- 모든 조각의 `span` 합 = `(end - start) / 5`
- `selectionArgs(320, 360)` → `{anchor:320, cursor:365}`
- `selectionArgs(360, 320)` → `{anchor:365, cursor:320}`
- `selectionArgs(320, 320)` → `{anchor:320, cursor:325}`
- `rowColOf(300)` → `{row:0,col:0}`, `rowColOf(1555)` → `{row:20,col:11}`
- `plusSlotFor`: 다음 블록까지 60분 이상 → 직전 길이만큼
- `plusSlotFor`: 틈이 직전 길이보다 좁음 → 틈 전체
- `plusSlotFor`: 다음 블록이 붙어 있음 → `null`
- `plusSlotFor`: `DAY_END`에서 끝남 → `null`
- `plusSlotFor`: 틈 정확히 5분 → 5분짜리

**link.js (2단계)**

- 블록 2개가 한 할 일에 연결, 하나만 ✓ → 할 일은 ☐
- 둘 다 ✓ → 할 일 ☑
- 할 일 ☑ → 블록 둘 다 ✓
- `removeBlock` → 할 일 생존, 미배정
- `removeTodo` → 연결된 블록 함께 삭제, 다른 블록은 생존
- `firstFreeSlot`: 빈 하루 → 05:00부터
- `firstFreeSlot`: 1시간이 안 들어감 → 가장 넓은 빈 구간

**store.js (2단계)**

- `todoId`가 그 날 todos에 없음 → `null`로, 블록 생존, `recovered: true`

**clipboard.js (2단계)**

- 연결된 쌍을 복사해 붙여넣으면 새 블록이 **새 할 일**을 가리킨다 (원본 아님)
- `merge`에서 블록이 겹쳐 버려져도 할 일은 남아 미배정

## 브라우저 (실제 렌더 필요)

- 격자가 390px에서 가로 스크롤을 만들지 않는다
